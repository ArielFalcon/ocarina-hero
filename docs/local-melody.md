# Local melody inference

Install Python 3.10, Git, and network access, then run `npm run setup:melody`. If `python3` is not Python 3.10, setup selects `python3.10` from PATH; install it there if unavailable. The installer creates `.runtime-melody/venv`, checks out the official source at commit `6d9d758f167d5fd2b56aa26da0618c4d451896b2`, checks the melody checkpoint SHA-256, and applies the upstream NumPy integer compatibility fix. It also fetches the Basic Pitch note model (`nmp.onnx`, Apache-2.0) from `spotify/basic-pitch` commit `9991303bba609a3b93089d13ec80d1d495083596` (v0.4.0) with Git into `.runtime-melody/basic-pitch/`, verifies its SHA-256, and installs the pinned `onnxruntime`. No system Python packages are modified. Analysis does not download anything. The local runtime can be removed and recreated at any time.

The upstream source is MIT licensed; its notice is in `.runtime-melody/source/LICENSE`. Separate checkpoint and training-data rights have not been established. The checkpoint is downloaded locally and must not be redistributed without resolving those terms.

The Vite dev and preview middleware accepts same-origin mono little-endian Float32 PCM at `/api/melody?sampleRate=44100`, with `application/octet-stream`. Inputs are limited to fifteen seconds. Only one inference can run at a time. If the runtime is missing or broken, rerun setup; no alternate extractor is substituted. Main melody is the default analysis mode. Its raw score is not a calibrated confidence or an accuracy claim.

## Decoding

Two local models run on the same fragment. Melodic SegNet gives a per-frame predominant-pitch salience; Basic Pitch gives per-frame note posteriors for all simultaneous notes. `scripts/melody_decoder.py` pools SegNet bins by semitone, mixes in the Basic Pitch posteriors as absolute probabilities (never normalized per clip, so a fragment without melody stays silent) with a mild preference for higher voices, and finds one monophonic path with a Viterbi pass that penalizes pitch changes and voicing switches. Notes shorter than a minimum duration are absorbed into a touching neighbour or dropped. The minimum follows the fragment's rhythm: half the mean spacing of Basic Pitch onsets while a note sounds, between 40 and 90 ms, so fast passages keep their sixteenth notes and slow ones stay free of fragments. Returned frames carry the decoded semitone centre; `engine.decoder` and `engine.basicPitchSha256` record the decoder. The server rejects output from any other decoder or model.

The earlier decoder took the per-frame SegNet argmax. Half of its notes were shorter than 60 ms, so it produced about 2.7 times too many notes.

## Benchmark

`npx tsx scripts/melody-benchmark.ts [--json out/melody-benchmark/<name>.json]` runs the production inference and analysis on the first 15 seconds of the 29 corpus recordings. It compares them with the curated source melodies (note F1: same MIDI pitch after one global octave shift, onset within 100 ms, one-to-one matching), placed on each recording by `out/melody-benchmark/alignment.json` (offset, constant tempo scale, transposition; provenance in `out/melody-benchmark/README.md`), and also compares the adapted TABs by sounding pitch. Use `--inference <script>` to run an earlier inference script under the same conditions. The references are unvalidated arrangements with automatic alignment, so the scores compare pipeline versions; they are not absolute accuracy.

| Decoder (29 clips, means) | Note F1 | Precision | Recall | Adapted TAB F1 |
| --- | --- | --- | --- | --- |
| SegNet argmax (earlier) | 0.42 | 0.31 | 0.76 | 0.42 |
| Fused Viterbi v1 (fixed 90 ms minimum) | 0.67 | 0.69 | 0.70 | 0.66 |
| Fused Viterbi v2 (current: rhythm-adaptive minimum, lower voicing penalty) | 0.69 | 0.66 | 0.75 | 0.67 |

Parameters were chosen on the same corpus. Chosen on random halves and scored on the other half, the fused decoder kept a held-out note F1 of 0.65. v2 is better than the earlier decoder on 28 of 29 clips (worse on shinzou). Against v1 it gains most on fast or detached melodies (pirate +0.16, laputa +0.12, ff7-victory +0.07) and loses on green-hill (−0.11) and slightly on lavender-town, numb and once-upon-a-time (−0.03 to −0.04). A user-supplied fast reference outside the corpus (Coconut Mall, Final Lap, 0–12.6 s, `coconut-mall-final-lap` in the alignment file) scores 0.48 with the earlier decoder, 0.55 with v1 and 0.63 with v2. Silence, low-level and pink or white noise at 8–44.1 kHz, and an isolated click produce no notes. Rejected, measured alternatives: Demucs source separation before inference (no gain); splitting repeated notes on Basic Pitch onsets or harmonic-energy valleys (more false splits than recovered notes); context-based octave correction (no gain); RMVPE vocal pitch fused in (+0.02 on sung clips, worse on instrumental ones); temporal max or mean smoothing of SegNet evidence (higher frame pitch accuracy, no note gain); YourMT3+ (YPTF.MoE+Multi, 562 MB checkpoint, GPL-3.0 code) alone 0.48 and fused as a third source −0.008 held out, despite helping several sung clips; ~4 s per fragment on Apple MPS, 24–34 s on CPU (`../ocarina-tabs-media/main-melody-viability-2026-11-12/yourmt3-evaluation/`).

Known limits: repeated same-pitch notes without a gap still merge; very short detached notes whose model voicing flickers between frames can still be dropped; melodies buried under louder arpeggios (for example a harp accompaniment) can follow the accompaniment; sung pop scores lowest (about 0.55 note F1), partly because singers deviate from the MIDI references' timing. Run the decoder tests with `npm run test:melody`.

In the browser, load an audio file, select and preview a fragment of up to fifteen seconds, choose the analysis mode, then select **Analyze**. File, region and mode changes do not start inference automatically. Successful analysis produces the existing calibrated TAB for playback and practice; empty results and failures appear beside the editor.

The waveform uses display-only peaks. Analysis averages the selected samples from every channel of the retained decoded buffer, preserving that buffer's actual sample rate. Source notes and contours use fragment-relative time. The optional schema-version-1 `sourceWindow` field adds original start/end/duration provenance; documents without this field remain valid. The browser still decodes the entire file before selection, which can consume substantial memory for long recordings.
